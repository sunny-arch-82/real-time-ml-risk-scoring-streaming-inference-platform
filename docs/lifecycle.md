# Model lifecycle and evidence
Every model gets an immutable UUID complete bundle (preprocessor+estimator+calibrator+threshold+feature columns/version), checksum and metadata under models/. MLflow logs raw sklearn model versions plus complete bundle artifact and evaluation reports. Serving deliberately loads the complete local bundle; serving the raw MLflow sklearn flavor would bypass calibration/threshold and is unsupported.
Candidate alias is the latest trained candidate for bookkeeping, not automatically the best. Training recommends by validation average precision and leaves champion unchanged. Promotion checks configured absolute quality and comparable validation AP; local atomic pointer is authoritative. MLflow champion alias mirrors it, but alias and pointer are not a distributed transaction; failure between operations can diverge them. API checks pointer each request and reloads bundle on change, preserving feature history. Rollback only allows a previously promoted version, with compatible feature/checksum.
For changed data/retraining windows, automatic comparison rejects mismatched validation hashes. Score both candidates on the same independent holdout and create comparable validation metadata before extending promotion code; no unsupported forced-promotion override is included. Repeated tuning against one validation set overfits, so preserve untouched chronological test and new independent holdouts.
Training uses balanced Logistic Regression and balanced-subsample Random Forest, optional seeded RandomizedSearchCV within training, separate sigmoid/isotonic calibration, threshold objectives F1/min-recall/min-precision/FP-FN-cost/top-K. Top-K threshold ties can exceed capacity. Features core/full offer controlled ablation; comparisons are user-reviewed rather than invented results. Permutation importance on validation is correlational, not causal, and raw-model AP-based; no calibration importance claim.
Drift separates numeric PSI, categorical Jensen-Shannon divergence, probability PSI and recent labeled quality. Example thresholds require sufficient monitoring rows. Retraining recommendation requires enough user-declared genuinely new labels AND drift/performance/scheduled signal. It never automatically trains/promotes. Existing labels are not proof of new labels; count provenance is caller responsibility. Single-class windows have null ROC/AP. All risk probabilities are synthetic-task outputs, not calibrated real-world financial risks.
